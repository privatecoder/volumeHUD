# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

classicHUD is a headless macOS menu-less utility (`LSUIElement`, `.accessory` activation policy) that restores the classic volume and brightness HUDs on macOS Tahoe and hides the system ones. Swift 6, SwiftUI + AppKit, deployment target macOS 26.0. No third-party dependencies and no test target.

This repo is a personal fork of [volumeHUD](https://github.com/dannystewart/volumeHUD), renamed to classicHUD because it covers brightness too. Upstream release history in `CHANGELOG.md` keeps the old name on purpose, and the `showVolumeHUD` method name refers to the volume HUD, not the app.

## Commands

```bash
# Build (main, non-sandboxed target)
xcodebuild -project classicHUD.xcodeproj -scheme classicHUD -configuration Debug build

# Build the App Store / sandboxed variant
xcodebuild -project classicHUD.xcodeproj -scheme "classicHUD (Sandbox)" -configuration Debug build

# Format and lint (pre-commit runs swiftformat; swiftlint is strict and scoped to classicHUD/)
swiftformat --config .swiftformat classicHUD
swiftlint
pre-commit run --all-files

# Dead-code check
periphery scan

# Kill a running instance before relaunching (the main scheme's Run pre-action does this)
pkill -f classicHUD

# Reset permissions when testing Accessibility/event-tap behavior
tccutil reset Accessibility com.privatecoder.classichud
tccutil reset ListenEvent com.privatecoder.classichud
```

Build notes:
- `BuildNumber.xcconfig` is gitignored and regenerated by the `classicHUD` scheme's Build pre-action from `git rev-list --count HEAD`. The pre-action also runs under `xcodebuild`, so command-line builds from a fresh clone work.
- If `xcodebuild` fails with a plug-in loading error, run `xcodebuild -runFirstLaunch` once.
- Debug bundle ID is `com.privatecoder.classichud.debug`, release is `com.privatecoder.classichud`, sandbox is `com.privatecoder.classichud.mas`. Accessibility grants are per bundle ID, so debug builds need their own permission grant.
- Signing is ad hoc (`CODE_SIGN_IDENTITY = "-"`, no team), so no paid developer account is needed. The ad hoc signature changes whenever the signed app changes, so macOS may ask for Accessibility again after rebuilding.
- This fork has no release or Homebrew distribution. `releases/` and `scripts/` are gitignored, and the VS Code workspace still lists upstream's sibling `../homebrew-apps` folder, which may not exist here.

## Architecture

All source lives flat in `classicHUD/`. Shared helpers: `Settings.swift` (defaults keys, registered in `ClassicHUDApp.init`, and `MonotonicClock`, which all timing heuristics use), `AudioOutput.swift` (CoreAudio access and the shared `DefaultOutputDeviceObserver`), `DisplayBrightness.swift` (DisplayServices, loaded once and never unloaded) and `SystemDefinedEventObserver.swift` (listen-only key observation shared by both monitors). Both observers are `.shared` singletons: owners `subscribe` and `unsubscribe` with a token, subscribe before reading current state, and compare reported values with their own. The Xcode project uses file-system-synchronized groups, so new `.swift` files in that folder are picked up automatically.

**Two targets, one source tree.** The `classicHUD (Sandbox)` target defines `-D SANDBOX` and excludes `MediaKeyInterceptor.swift` and `BrightnessMonitor.swift` from membership. Any code touching key interception, event taps, Accessibility, brightness, or GitHub update checks must be wrapped in `#if !SANDBOX` (see `ClassicHUDApp.swift`, `VolumeMonitor.swift`, `HUDController.swift`, `AboutView.swift`). Check that both schemes still compile after such changes.

**Runtime wiring** (set up in `AppDelegate.applicationDidFinishLaunching` in `ClassicHUDApp.swift`):
- `HUDController` owns the borderless HUD `NSWindow` hosting the SwiftUI `HUDView`, handles show/hide timing, and picks the screen (primary display, or the one under the mouse when "follows mouse" is on).
- `VolumeMonitor` *observes* volume via CoreAudio property listeners on the default output device, follows default-device changes, and uses key-press timing from `SystemDefinedEventObserver` to decide whether a change was user-initiated before showing the HUD.
- `BrightnessMonitor` does the same for built-in display brightness by polling `DisplayBrightness` every 0.1s. It runs only while the `brightnessEnabled` setting is on, and the settings toggle starts and stops it.
- `MediaKeyInterceptor` (since v3.0) installs a CGEvent tap that *consumes* volume/brightness media key events (`NSSystemDefined`, subtype 8), applies the change itself through CoreAudio / `DisplayServices`, and shows the HUD. Consuming the event is what suppresses the system HUD.

**Interceptor/monitor coordination.** Both the interceptor and `VolumeMonitor` see the same volume change. The interceptor stamps `lastVolumeChangeTime`, and `VolumeMonitor` skips its HUD update within `volumeChangeCooldown` of that, to avoid double HUDs.

**Safety fallback.** If the interceptor fails to read or set volume, mute, or brightness (or brightness doesn't change), it flips `volumeInterceptionWorking` / `brightnessInterceptionWorking` to false and passes keys through from then on. The change is applied synchronously inside the tap callback, so the consume decision is made with the outcome known: a failure before anything changed passes the press through, and a failure after a change was applied still consumes it, or macOS would apply it twice. Keep the callback to a fixed, small amount of work (a few CoreAudio/DisplayServices property calls; their latency is up to the driver). The HUD, the feedback preference lookup and the sound run afterwards in a `Task`. `consumeKeyUp` tracks each hold using the repeat flag: a key-up is consumed only when the tap saw the hold's first key-down and consumed every key-down since. A repeat without a tracked hold, or any hold active when macOS disables the tap, hands the key-up to macOS. Brightness keys are only intercepted while the brightness HUD setting is on. This resets only on audio device change, display change, or app restart. Preserve this behavior: a user must never be left unable to change volume.

**Volume stepping.** Standard step is 1/16, Option+Shift gives 1/64. The interceptor tracks `VolumeControlState` (requested vs. read-back volume) so devices with uneven hardware steps keep advancing from the logical target. The HUD displays the quantized requested value, not the read-back. Volume reaching 0 auto-mutes and raising it auto-unmutes, mirroring macOS. Shift toggles the feedback sound relative to the system "play feedback" preference.

**Permissions.** If the interceptor can't start at launch, `AppDelegate` retries every second until it does, restarting key observation once when Accessibility becomes trusted. Everything degrades gracefully without Accessibility: the system HUD still shows alongside ours and boundary (0%/100%) presses can't be detected. Code should keep working when `AXIsProcessTrusted()` is false.

**Other pieces.**
- `AboutView` is the settings window shown when the app is launched a second time (`applicationShouldHandleReopen`). Settings are `@AppStorage` / `UserDefaults` keys: `brightnessEnabled`, `classicHUDFollowsMouse`, `useRelativePositioning`.
- `LoginItemManager` uses `SMAppService`.
- `AppDelegate` also detects a conflicting instance running from another bundle path and quits, and suppresses the startup notification when launched as a login item, based on system uptime.
- `Logger.swift` wraps unified logging and only builds a message when its level is enabled. Use it instead of `print`.
- Preview mode: monitors and `HUDController` take `isPreviewMode` and skip all system hooks. The app delegate bails early in SwiftUI previews.

**Concurrency.** Swift 6 with approachable concurrency. The monitors, interceptor and HUD controller are `@MainActor`. Event tap run loop sources, CoreAudio listener queues, and timers are all on the main thread, so C callbacks enter the actor with `MainActor.assumeIsolated`; keep it that way or those calls trap. Tap callbacks must return pass-through events with `passUnretained`. The interceptor applies changes inside its callback and defers UI work. Event taps must be torn down fully on stop, and must not be installed twice.

## Conventions

- SwiftFormat config is extensive and enforced on commit. It requires the file header `{file} / by Danny Stewart ({year}) / MIT License / repo URL`, `MARK:` organization of types and extensions, trailing commas, and explicit `self` removal. Run it rather than hand-formatting.
- `CHANGELOG.md` follows Keep a Changelog. Add user-facing changes under `## [Unreleased]`.
- Commit messages use Conventional Commits with scopes, e.g. `fix(volume): ...`, `chore(release): bump version to X.Y.Z`. `MARKETING_VERSION` in `project.pbxproj` is bumped in release commits.
